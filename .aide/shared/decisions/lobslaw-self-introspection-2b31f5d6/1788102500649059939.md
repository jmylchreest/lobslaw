# lobslaw-self-introspection

**Decision:** Introspection tools are operator-gated. The debug_* family is disabled by default; the agent must never assert system state it has not checked, and must say it cannot verify rather than guess when the tool it would need is not registered.

## Rationale

The debug_* family describes the deployment rather than acting on it — debug_soul returns the persona text, debug_providers the configured endpoints and models, debug_policy the rules gating every other tool. A steered model can be talked into reciting any of it into whatever channel it is answering, so the family arrives off and an operator turns it on knowingly. The honesty requirement is separable from the tooling and survives it: not being able to check is a fact to report, not a licence to guess.

## Details

Every registered tool reaches the model each turn; registration is the only gate. Disabling a tool therefore removes it entirely rather than merely deprioritising it.
memory_recent is not part of the debug_* family and stays registered, so the commonest failure — claiming memory is empty when it is not — remains checkable on a default deployment.
Enable the family with disabled_tools = ["remote_*"], which names only the other default and so leaves debug_* on. The list replaces the defaults rather than adding to them.
The system prompt must not instruct the model to call tools it may not have. Prompt text naming specific introspection tools has to be generated from the live tool list, as the capability block already is; a hardcoded instruction to call debug_tools is a prompt that contradicts the schema on any deployment that has not opted in.
A deployment answering only to its operator is the case for turning the family on. One answering to people who are not the operator is the case the default is set for.
