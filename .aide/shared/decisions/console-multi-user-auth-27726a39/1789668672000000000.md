# console-multi-user-auth

**Decision:** Console identity comes from per-user tokens in [[user]]; every handler gates itself

## Rationale

Reuses the principals, roles and policy engine already present rather than adding an identity system, so per-user authorisation costs almost nothing. A person without console_token_ref cannot sign in, deliberately: [[user]] is also where a Telegram chat id is bound and binding a chat must not hand out a login. There is no auth middleware on the console surface — routes bind straight to handlers — so each handler authenticates itself or is open. Two shipped open: /v1/groups, and /v1/prompts, which approves guarded tools. A table-driven route test now fails when a route is added without gating.

## Details

The absent middleware is the risk worth naming: registerRoutes binds paths straight to handlers, so forgetting one line leaves a route open and nothing anywhere says so. TestConsoleRoutesRefuseUnauthenticatedCallers is the compensating control and covers the whole console surface — bots, inbox, activity, sessions, config, groups and prompts — with every registry populated, because a handler that 503s on a nil registry never reaches its auth check and would pass while open.
