# existing-codebase-precedence

**Decision:** The repository is the authority. Where an established convention in this codebase conflicts with general best practice or any imported language blueprint, follow the codebase and raise the divergence separately.

## Rationale

A convention that is consistent across a codebase has value beyond whether it is optimal — it makes every file predictable, keeps diffs reviewable, and encodes decisions the team may have made for reasons that are not visible in the code. Changing it as a side effect of unrelated work converts a small reviewable change into a large one, mixes two concerns in a single review, and silently discards a decision nobody agreed to revisit. Best-practice blueprints describe the target state for new work; they are not a licence to retrofit.

## Details

Precedence, highest first: (1) explicit instruction in this task, (2) recorded aide decisions for this project, (3) conventions observable in the surrounding code and committed config, (4) language/framework blueprints, (5) general best practice. A convention counts as established when it holds across the module you are touching, not because a single file does it. When you believe an established convention is wrong, say so once, in the summary of your work, with the concrete cost — then implement it the existing way. If the divergence is worth acting on, record it with `aide task create` or `aide decision set`, never as an unrequested edit.
