# lobslaw-mcp-transport-and-egress

**Decision:** An MCP server is declared with a transport: stdio (subprocess, the existing shape) or a remote URL over SSE/streamable HTTP. Every server, both kinds, is pinned to egress role mcp/<name>, and for a remote server the ACL is DERIVED FROM ITS OWN URL host rather than written a second time. Servers declared in [[mcp.servers]] or .mcp.json are operator provenance and immutable at runtime; anything the agent registers is a proposal that an operator approves before its tools reach the registry, and can never overwrite an operator-declared name. Provenance is by location, not a field: there is no marker to forge or lose.

## Rationale

The pinning mechanism was already 80 percent built and switched off by one empty map: egress.ForMCP, ACLInputs.MCPServerNetworks and proxyEnv(mcp/<name>) all exist, but wire_egress.go sets MCPServerNetworks to an empty map unconditionally. The effect was the worst of both — a server honouring HTTPS_PROXY was denied every call, and one ignoring proxy env was unrestricted. Remote MCP is MORE confinable than stdio, which inverts the usual intuition: lobslaw makes the HTTP call itself through egress.ForMCP, so the pin is enforced in-process and the server cannot opt out, where HTTPS_PROXY for a subprocess is advisory. Deriving the ACL from the URL follows [[remote]], where role remote/<name> reaches exactly that remote's host and no second list can drift. Operator-versus-proposed provenance mirrors the self-taught store for the same reason it works there.
