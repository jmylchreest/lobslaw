# lobslaw-soul-effective-state

**Decision:** SOUL.md is the operator-owned node-local baseline; bounded agent edits persist in a revision-checked Raft overlay. All consumers use the merged effective soul. New turns snapshot it once into system configuration; resumed turns retain their original prompt. Soul guidance describes how to answer and must never be treated as the user question or acknowledged as a request. Reload keeps the last valid baseline on invalid or missing files; explicit overrides survive reload, clamp to current baseline bounds, and can be reset to inheritance. Compute-only tuning uses cluster storage and policy evaluation; there is no successful volatile-write fallback.

## Rationale

The loader, adjuster, and agent had separate state paths, so Markdown and persisted edits were invisible to the model while introspection could be stale. User explicitly requested full wiring while preserving the fix for responses answering soul configuration. This supersedes the file-write/storage-location clauses of the original soul-adjustment and soul-culture decisions; it does not enable passive feedback adaptation or introduce new schema keys.
