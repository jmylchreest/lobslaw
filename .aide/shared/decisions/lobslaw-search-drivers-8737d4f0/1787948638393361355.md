# lobslaw-search-drivers

**Decision:** Web search backends join the DriverSet waist as SearchDriver, with two tiers: compiled drivers for engines with real behaviour (exa, searxng) and a declarative `driver = "template"` that describes any other engine entirely in TOML — options/extra_params/response as map[string]string, dot-paths into the response JSON, auth via the existing StaticCredential/QueryCredential. Selection is [compute.web_search] providers = [labels] over [[compute.search_providers]] entries, ordered as a failover chain. web_search now routes through egress.For("web_search") with a role derived from the selected endpoints, and registers through failoverBuiltin so the soul trust floor is enforced. The pre-driver api_key_ref-only config still means Exa.

## Rationale

`web_search` was the one pluggable-looking thing that was not pluggable: Exa inlined in the builtin, a `WebSearchConfig` of `{api_key_ref, endpoint}`, and no way to run a self-hosted SearXNG — a poor fit for a project whose first line is "privacy- and security-first". Three things were wrong beyond the missing feature, and all three were documentation describing code that did not exist:

- `docs/docs/configuration/reference.md` documented `provider = "tavily"`. koanf dropped the unknown key and the operator got Exa anyway.
- `docs/docs/security/egress-and-acl.md` documented a `web_search` role. `internal/egress/builder.go` never created it, and the builtin used a bare `http.Client` — the only builtin outside the proxy.
- `read_image` and `read_audio` wrap their handlers in `failoverBuiltin`, which enforces the soul's `min_trust_tier`. `web_search` took a single non-variadic config and did neither, so the builtin that hands the user's own words to a third party was the one that never checked the tier.

**Why two tiers rather than one.** Search is the shallowest modality lobslaw talks to. Brave, Tavily, Serper, Google CSE and every corporate search proxy differ only in which parameter carries the query and which JSON path carries the results. A Go file per engine would make a field mapping into a rebuild and a release. `docs/dev/PROVIDERS.md` had already argued for a declarative template driver and deferred it on the grounds that "an extension point proves nothing until somebody extends it"; search is where it stopped being theoretical, because the mapping genuinely is the whole driver.

**Why `map[string]string` rather than typed fields.** Typing each vendor's knobs into `SearchProviderConfig` would make every new engine a config-struct change — the exact cost the design removes. Factories validate their own keys at boot, so a typo is a start-up error naming the offending key rather than a surprise at the first search.

**The line the template driver does not cross** is one request and one response. A backend needing a second call, a request signature, or a pagination loop is real behaviour and gets a compiled driver. Growing the interpreter into a scripting language would recreate the problem it exists to avoid; the skill path in PROVIDERS.md is where that ends up.

**Not auto-punching RFC1918.** A self-hosted SearXNG lands on a private address every time, and smokescreen denies those regardless of the hostname ACL. Silently adding the CIDR would be a hole the operator never wrote down, so instead lobslaw warns at boot naming `security.egress_allow_ranges`. The failure it replaces is a proxy denial that names neither the range nor the setting.

**Resolution lives in `internal/node`, not `pkg/config`.** `pkg/config` parses and validates; the layer above decides what parsed values mean. `TestEverySettingIsReadBySomething` enforces this — a setting only read inside `pkg/config` counts as dead.

## Consequences

- Trust tiers now bite on search for the first time. A deployment already running `web_search` with a soul floor set must declare `trust_tier` on its provider; an undeclared tier is not evidence of a high one.
- `provider = "tavily"` in an existing config now fails at boot with "unknown search driver; available: exa, searxng, template" instead of being silently dropped. That is the intended outcome — Tavily ships as a documented template config.
- Adding a compiled backend stays one file plus one `RegisterSearch` line in `internal/node/wire_drivers.go`.
