# code-magic-numbers

**Decision:** A value with meaning gets a name. No inline literals for defaults, limits, timeouts, thresholds or protocol constants — declare a typed constant next to the thing it configures, and reference it everywhere else.

## Rationale

An inline literal is a copy, and copies drift silently. lobslaw shipped exactly that failure: DefaultDisabledTools gained debug_* while the lobslaw init template kept its own hardcoded ["remote_*"], so a freshly initialised deployment would have switched the family back on. Nothing caught it — the test asserted the template against a literal of itself, which only proves the template has not changed. A named constant would have made the second copy impossible to write.

## Details

Name it where it is owned: gateway.DefaultHeartbeat belongs in the gateway package, not in a shared bag. A central defaults/common package trades one problem for a worse one — it breaks locality, and go-project-structure already rules out utils/helpers/common names.
Anything rendered into generated output (lobslaw init's config template, docs tables, example configs) must be interpolated from the constant, never retyped. The template is a text/template already; a default belongs in its data, not its body.
Where a generated artefact states a default, a test must bind the two — parse the artefact and compare against the constant. Asserting a literal is not a test, it is a second copy with a t.Errorf attached.
Enums: a fixed set of string or int states gets a defined type plus constants, so the compiler rejects an unlisted value.
Not covered: 0, 1, -1 and other arithmetic identities; array indices; values used exactly once whose meaning is plain at the site and that nothing else can reference.
